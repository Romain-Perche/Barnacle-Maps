# Running, dependencies and external services

## Running locally

There is no build step and no package to install. `package.json` defines two scripts:

| Command | What it does |
| --- | --- |
| `npm start` | `python3 -m http.server 8000` — serves the repo root as static files. |
| `npm test` | `node --test test/` — runs the Node test suite ([Test suite](../testing/test-suite.md)). |

Open `http://localhost:8000`. Browsers only allow geolocation on secure origins, so use `localhost` or HTTPS. Without permission the status shows `Location unavailable. Allow location access to get directions.`; without the API, `Geolocation is not supported by this browser.` The map starts centred on Paris (zoom 13) and recentres on the first position fix.

Any static file host works for deployment as long as it serves over HTTPS and keeps the `src/` ES modules next to `index.html`.

## Dependencies

The repo has no lockfile and no npm dependencies; runtime code is plain ES modules. The software bill of materials, [`sbom/SBOM.md`](../../sbom/SBOM.md), is the authoritative list of third-party dependencies and versions and is regenerated by the factory — do not edit it. Leaflet (JS and CSS) is not installed locally: `index.html` loads a pinned version from the unpkg CDN as a global `window.L`. Tests need only Node's built-in test runner.

## External services called from the browser

| Service | Used for | Code |
| --- | --- | --- |
| `tile.openstreetmap.org` | Map tiles, and zoom-16 tiles read pixel by pixel for [pleasure](../features/pleasure.md) | `TILE_URL`, `loadTile` in `src/app.js` |
| `nominatim.openstreetmap.org` | Place [search](../features/search.md) | `searchUrl` in `src/geo.js` |
| `routing.openstreetmap.de/routed-foot`, `/routed-car` | OSRM [routing](../features/routing.md) | `TRAVEL_MODES` in `src/geo.js` |
| `unpkg.com` | Leaflet library and stylesheet | `index.html` |

All are free public services with usage policies (Nominatim: about 1 request/s, no heavy use; OSM tiles: no bulk downloading). The app mitigates this with a 500 ms search debounce, at most 150 pleasure tiles per computation and no pleasure scoring for long walks, but it sets no custom contact header and has no caching layer. Heavy production use would need your own or commercial tile/geocoding/routing providers; the base URLs are centralised constants for that purpose.

## Security and privacy notes

- The user's position is sent to the routing server as the route start (and nowhere else); it is not stored.
- Search queries go to Nominatim.
- Place names from Nominatim are inserted with `textContent` (buttons, stop names), not as HTML. The stop marker's `divIcon` HTML contains only its number.
- The Leaflet script from unpkg is loaded without Subresource Integrity, so the page trusts the CDN.
- No secrets, API keys or cookies are used.
