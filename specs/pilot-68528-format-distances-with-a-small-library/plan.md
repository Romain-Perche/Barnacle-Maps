# Implementation Plan: Format distances with a small library

**Branch**: `factory/pilot-68528-format-distances-with-a-small-library` | **Date**: 2026-11-13 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/pilot-68528-format-distances-with-a-small-library/spec.md`

## Summary

Replace the hand-written unit selection and rounding in `formatDistance` (`src/geo.js`) with the
npm package **`convert` 8.0.2** (MIT, zero dependencies, ESM). The function rounds to whole metres,
lets `convert(m, "m").to("best", "metric")` pick `m` or `km`, and prints at most one decimal place
with no trailing ".0" ("420 m", "1.5 km", "2 km", "12.3 km", "1234.6 km").

The browser loads the package from unpkg at a pinned version through an **import map** in
`index.html`, so the bare specifier `"convert"` resolves to the CDN in the browser and to
`node_modules` in the Node tests. `src/geo.js` starts a **non-blocking dynamic import** that never delays the app. Until the
package has loaded, or if the CDN fails, the app keeps working and distances use the fallback format
(whole metres, e.g. "1500 m", pending CHK006). Durations and everything else stay the same.

## Design Notes

- **Import** (top of `src/geo.js`): `let convert;` and
  `export const distanceFormatReady = import("convert").then((m) => { convert = m.convert; }, () => {});`
  Only a dynamic import can be caught. A static `import` that fails would stop `app.js` from
  loading at all, which FR-006 does not allow. There is no `await` at module level, so the map and
  search never wait for the CDN (spec clarification CHK022). Tests `await distanceFormatReady` in
  a `before` hook.
- **Signature**: `formatDistance(meters, conv = convert)`. The default reads the live `convert`
  binding at each call. The optional second parameter lets the tests check the fallback without
  mocking modules. Call sites stay the same.
- **Logic** (no hand-written unit selection or km rounding, SC-005):
  1. Not a finite number, or negative → `"—"` (neutral placeholder, FR-008).
  2. `m = Math.round(meters)`. This makes 0.4 → 0 and 999.6 → 1000, so the result is "1 km".
  3. No package (`conv` is undefined) → `` `${m} m` `` (plain fallback; follows FR-002/FR-004, and FR-003 "where possible" is not met).
  4. `m === 0` → `"0 m"` (the package's "best" unit for 0 is `mm`).
  5. Otherwise `{ quantity, unit } = conv(m, "m").to("best", "metric")` → `` `${+quantity.toFixed(1)} ${unit}` ``.
     For whole metres ≥ 1, "best" returns only `m` or `km` (it never goes above km, which was
     checked up to 10⁹ m). `+x.toFixed(1)` removes a trailing ".0" and never adds a thousands
     separator.
- `formatDuration` and every other helper stay unchanged (FR-007).

## Decisions Taken Without Asking (non-interactive run)

- Package: `convert` (see research.md §1). The spec only requires "small, well-known".
- Invalid-distance placeholder: `"—"` (em dash). The spec allows "nothing or a neutral placeholder". An empty string would leave a "Route 1 ·  · 5 min" title.
- Negative distances count as invalid. OSRM never returns them.
- Fallback format: whole metres only. Keeping a hand-written km branch would go against SC-005, and FR-006 only asks for "where possible".
- Version pin: exact `8.0.2` in both `package.json` and the unpkg URL, so tests and browser run the same code.
